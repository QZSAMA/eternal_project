# Eternal 后续优化与新功能项目推进方案书

## 1. 目标与原则

本方案以“求婚现场一次成功”为第一目标，以当前基线提交 `781f1da801db29fb6d8718a26c4a98ceb0ac4ba2` 的审查证据为输入。路线分为可靠性修复、可测试架构、体验完善和可选新功能四条流；每条流都有独立验收，避免把大重构和内容创作绑定在一起。

原则：

- P0 先于一切视觉/内容增量。
- 运行时继续保持离线优先；开发依赖可以存在，但交付包不能依赖网络。
- 行为变更严格 TDD：先失败测试，再最小实现，再重构。
- 所有个人信息和文案从 `storyData.js` 注入，素材变更经过授权/隐私检查。
- 每个阶段结束都能生成一个可演示包，失败时仍能跳过小游戏完成求婚。

## 2. 目标架构

```text
CONFIG + validateConfig
          │
          ▼
纯状态机（无 DOM） ──► Renderer DOM/Canvas
          │                    │
          ├──► AudioAdapter     ├──► 2D MiniGame（默认）
          └──► StoryRunner      └──► WebGL MiniGame（可选增强）
```

目标不是一次性拆成复杂框架，而是先把“状态、资源、渲染、输入”边界变成可测试接口：StoryRunner 只推进指令；渲染器只接收状态；小游戏以 `start/stop/onEnd` 适配器接入；音频和资源加载可以被 fake。这样既可保留当前原生 JS，也能按需迁移 ES Modules。

## 3. 分阶段执行

### 阶段 0：发布阻断清零（P0，先行）

**目标**：断网、无 WebGL、缺 BGM 时仍能完成求婚。

任务：

1. 将 Three.js 锁定版本 vendored 到 `vendor/`，或将小游戏回退为 Canvas 2D；入口不再引用远程 URL。
2. 在 `Minigame.start` 前做 `typeof THREE`/WebGL 探测；失败时进入 2D 兼容小游戏或明确调用 `onEnd('skipped')`。
3. 为 BGM 建立资源 manifest：缺失文件不重复请求，UI 显示一次“未提供音乐，使用合成音效”。
4. 增加无网络 Playwright smoke：拦截所有外链，覆盖 `gaming` 和 `first_date` 两条路径。

验收：无网络浏览器连续运行到 `.layer-ending.is-show`；控制台没有 ReferenceError/未处理 Promise；小游戏失败/跳过均在 1 个用户动作后返回主线。

### 阶段 1：契约与测试基座（P1）

**目标**：让剧情、资源和小游戏规则可验证。

任务：

1. 提取 `validateConfig(config)`，校验 meta、背景、角色表情、照片 key、音频 key、jump 目标和指令字段。
2. 将 `Engine._exec` 的未知指令/label 改为可定位错误；生产模式提供返回开始和跳过章节按钮。
3. 把 `callMinigame` 改为接收明确的小游戏配置，不再丢弃 `arg.minigame`；清理或实现 `playerHP/meiR/orbR` 等参数。
4. 为纯状态转移、配置校验、`_photoPath`、时间换算编写单元测试；为完整用户路径编写 Playwright smoke。
5. 加入 `npm` 仅用于开发测试的最小脚本（runtime 仍保持零外部依赖），并在 CI 运行 `node --check`、单测和浏览器 smoke。

验收：任意错误 label 在启动阶段被指出；修改姓名/日期/路径不需改引擎；测试能复现并阻止已知 P0/P1 回归。

### 阶段 2：素材与内容质量（P1）

**目标**：让演示内容具备可信的视觉交付质量。

任务：

1. 重新导出 6 张透明角色立绘（PNG/WebP），去除 AI 水印，确认授权与隐私；将格式和尺寸写入 manifest。
2. 使用 WebP/AVIF 派生图，保留高分辨率源文件在不随运行包分发的位置；首屏只预加载当前背景和首个角色。
3. 将真名、结束文案、蒙太奇字幕和拒绝彩蛋全部移入 `CONFIG`；reveal UI 使用 `textContent`。
4. 决定 BGM 策略：提交四首已授权 MP3，或将字段设为空并把“静默演示”写入 README；两种模式都不产生 404。
5. 统一 README、原计划、实现计划和压缩包说明，以实际采用的 2D/Three.js 架构为唯一规格。

验收：素材清单可机器校验；所有角色无矩形背景/水印；压缩包在另一台机器解压后资源路径全部 200；文案定制只改 `storyData.js`。

### 阶段 3：输入、可访问性与现场 UX（P1）

**目标**：键盘、鼠标、触屏、低动效偏好都能完成主线。

任务：

1. 统一 Pointer Events；实现虚拟摇杆、触控瞄准和点击发球，并保留 WASD/鼠标/右键/E。
2. 增加对话 `aria-live`、菜单焦点管理、按钮 `:focus-visible`、小游戏结果公告和错误诊断层。
3. 移除 `user-scalable=no`；增加窄屏/竖屏提示和安全区布局。
4. 增加 `prefers-reduced-motion`：暂停 Ken Burns、呼吸、戒指旋转、按钮脉冲和粒子循环。
5. 将小游戏提示从底部叠层移入独立 HUD，完成 1280×720、1920×1080、竖屏截图验收。

验收：键盘 Tab 可到达所有操作；屏幕阅读器能获知台词/菜单/结果；触屏设备无需右键或悬停即可完成小游戏；低动效模式没有持续循环动画。

### 阶段 4：游戏稳定性与性能（P1/P2）

**目标**：不同设备帧率下机制一致，重复运行不积累 GPU 资源。

任务：

1. 将移动、球体、敌人和粒子速度改成单位/秒；采用固定步长或插值，注入时钟和随机数源。
2. 明确小游戏成功/超时/跳过三种结果；如果保留“不会卡关”，把复活逻辑写成可测试状态而不是 `Math.max(1, ...)` 隐式实现。
3. 复用几何体/材质/粒子对象；集中释放纹理、材质、renderer；停止所有 RAF 和输入监听。
4. 增加性能采样：长时间运行时粒子数量、纹理内存、主线程帧时间和低端设备降级策略。

验收：同一输入脚本在 30/60/120 FPS 模拟时结果一致；小游戏退出后无 RAF/事件监听残留；低端设备仍可通过跳过路径完成求婚。

## 4. 新功能候选与优先级

### 4.1 A 级：内容预检与演示模式

新增一个不依赖后端的“演示预检”入口：扫描 `CONFIG` 和本地资源，显示缺失照片/BGM、角色透明度、预计时长、输入方式和“离线已验证/未验证”状态。它直接解决当前最昂贵的现场风险，优先级高于新章节。

### 4.2 B 级：章节选择与排练模式

在开发模式加入隐藏快捷键或 URL 参数，允许从 `gaming`、`montage`、`proposal` 直接排练；支持跳过打字机和自动等待，但生产模式保持关闭。该功能能把每次排练从完整流程压缩为几分钟，并让 smoke 测试更稳定。

### 4.3 B 级：多结局但不阻塞主线

把“小游戏成功/跳过/超时”映射到不同字幕或照片顺序，所有结果都汇合 proposal。这样增加参与感而不引入失败卡关；每个结果必须有独立回归测试。

### 4.4 C 级：本地内容编辑器

提供静态 HTML 的表单，将姓名、日期、台词和照片选择写回可下载的 `storyData.js`。由于涉及个人照片和文件权限，先以开发者工具/预检报告替代，待内容契约稳定后再立项。

### 4.5 暂缓功能

存档/读档、账号、云同步、在线排行榜、远程素材库不符合一次性离线求婚场景，也会扩大隐私和网络依赖面，当前不立项。

## 5. 里程碑、角色与交付物

| 里程碑 | 主要交付物 | 退出条件 |
|---|---|---|
| M0 可靠 | vendored/fallback 游戏、资源 manifest、离线 smoke | P0-001/P0-002 关闭 |
| M1 可测试 | `validateConfig`、单测、浏览器 smoke、CI | P1-006/P1-007 有回归测试 |
| M2 可定制 | 透明角色、音频策略、统一文档和压缩包 | 资源 200、无水印、零 404 |
| M3 可现场 | 触屏、焦点、低动效、HUD 布局 | 三种输入与目标分辨率通过 |
| M4 可演进 | dt 物理、对象池、预检/排练模式 | 性能与功能基线稳定 |

建议角色分工：产品/内容负责人维护 `storyData.js` 与授权清单；前端负责人维护 Engine/Renderer/Minigame；QA 负责人维护 smoke 和截图矩阵；发布负责人只从已通过门禁的工作树生成压缩包。

## 6. 风险与决策点

需要用户在 M0 前确认的唯一架构决策是：

1. **Canvas 2D 回归（推荐）**：彻底符合零依赖/离线承诺，兼容性最好，视觉上牺牲部分 3D 效果。
2. **保留 Three.js + 本地 vendoring + 2D fallback**：保留当前 3D 资产和机制，代码复杂度与包体略增，但可渐进迁移。

无论选择哪条路径，都不接受仅保留远程 CDN 而没有降级。该决策会写入 `docs/project-memory.md` 和一条 ADR，并触发一次完整 smoke/性能复审。

## 7. 首个迭代的 TDD 骨架

建议先写以下失败测试，再实现代码：

```text
1. validateConfig 拒绝未知 jump label，并返回文件/指令索引。
2. 外链被拦截时，小游戏调用 onEnd('skipped') 且 Engine 进入下一句。
3. 缺失 BGM 不产生重复请求，音频状态显示 muted-fallback。
4. 修改 realHeroName/realHeroineName 后 reveal 文案使用新值。
5. 30 FPS 与 60 FPS 的同一输入序列得到相同 healCount/结果。
6. 触屏点击/虚拟摇杆可以移动玩家并触发黄球发射。
```

每个测试都必须先观察到符合预期的失败，再提交最小实现；测试通过后才允许抽象 Renderer、AudioAdapter 或新的小游戏接口。
