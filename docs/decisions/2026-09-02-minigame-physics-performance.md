# ADR：小游戏 `dt` 物理与特效预算

- 日期：2026-09-02
- 状态：已采用

## 决策

3D 小游戏保留现有 60 FPS 手感作为基准，但所有运行时更新都按受限 `dt` 推进：

1. `Minigame.loop()` 将每帧时间限制在 0–50ms；无效或负值按 0 处理。
2. 玩家移动使用秒级速度积分；球体、敌人、光环、粒子和拖尾使用 60 FPS 基准比例缩放，保证 30 FPS 下总时长内位移和寿命不漂移。
3. 3D/2D 更新共享一次循环时间戳，避免同一帧重复调用 `performance.now()`。
4. 球体碰撞使用 x/z 平面平方距离，避免碰撞热路径创建临时 Vector3。
5. 粒子和拖尾设置固定数量上限，超过上限时回收最旧对象并释放几何体/材质。

## 原因

原 3D 逻辑把移动、速度、生命周期和动画写成每帧常量，在低帧率或恢复后台时会导致速度、碰撞和特效寿命变化。更新循环中的 `clone()` 和无限特效增长也会增加 GC 与 GPU 压力。此次方案只做保守的时间换算和预算保护，不改变配置数值、胜负条件或渲染降级。

## 结果与代价

- 60 FPS 下玩家、球体、敌人和特效保持原有数值表现；大于 50ms 的卡顿会被分段限制，避免瞬移。
- 3D 更新新增少量时间换算和拖尾累加器；粒子/拖尾上限可能在极端连续命中特效时丢弃最旧视觉效果，但不影响游戏规则。
- Three.js classic build 的弃用 warning 仍存在；ES Module 迁移作为独立后续工作。

## 验证

- `tests/minigame-physics.test.js`：`dt` 限制、60/30 FPS 积分一致、3D 玩家移动一致、平方距离和特效队列回收。
- `tests/smoke-relationship-ux.py`：`gaming`、`first_date` 主线通过。
- `tests/smoke-touch-minigame.py`：触屏 2D 与桌面路径通过。
- `npm test` 40/40、`npm run check`、`git diff --check` 通过。

## 复查触发器

- 改变玩家/球体/敌人速度或生命周期配置。
- 引入固定时间步、物理引擎、对象池或新的粒子系统。
- 升级 Three.js、迁移 ES Module 或需要在低端移动设备上提高特效上限。
