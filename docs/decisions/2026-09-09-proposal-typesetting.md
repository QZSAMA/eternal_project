# 求婚文案与结尾排版

用户指定求婚画面三段文案、接受后的英文大标题以及右下角日中双语题字。本次采用“但是， / 他还想和你一起，创造更多美好的回忆。 / So… Will you marry me?”；“还想和你一起”承接已经展现的回忆，英文使用自然的句式大小写与省略号。斜线处为实际换行。

## 实现与约束

- 沿用唯一的 `meta.proposalCopy` 字符串，以 `white-space: pre-line` 显示换行，不增加第二套求婚文字。
- `meta.endingTitle`、`meta.endingSubtitle`、`meta.endingContinuation` 集中维护结尾文字；非字符串值在配置校验时提示。
- 接受后 `SHE SAID YES !!` 为 148px 舞台字号的大标题；中文作为副标题；右下角显示“つづく”和“未完待续”。舞台随窗口等比缩放。
- 保留戒指延迟渐显、结尾停留和重启确认交互。无新增资产和运行时依赖。

## 验证

- 先验证配置契约和浏览器文案断言失败，再修改实现。
- 运行完整 Node 测试、语法检查、差异空白检查。
- 使用静默 Chromium 检查 1280×720、844×390、390×844（低动效）布局，以及求婚 → 接受 → 结尾 → 取消重启。浏览器阻止非本地请求，截图用于视觉复查。

实际结果：58/58 Node 测试通过；语法与差异空白检查通过；三种窗口的布局 smoke 和现有回忆轮播到求婚 smoke 均通过。竖屏维持现有横向舞台等比缩放，内容无裁切，但观看建议使用横屏。

## 复查触发器

更改换行、字号、舞台缩放或结尾题字时，重新运行 `tests/smoke-proposal-layout.py`。
