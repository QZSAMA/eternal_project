# Eternal 项目审查与治理文档设计

## 目标

为 `trae/agent-1maClB` 建立一个可持续维护的工程基线，覆盖架构、内容、功能、界面、可访问性、运行可靠性及后续项目推进。首轮只新增文档与治理规则，不改变现有业务代码。

## 范围与事实基线

- 审查对象：提交 `781f1da801db29fb6d8718a26c4a98ceb0ac4ba2`。
- 运行形态：静态 `index.html`，原生 JavaScript，Canvas 粒子层，Three.js 小游戏。
- 交付约束：离线双击运行、1920×1080 投屏、文案/素材可配置、求婚流程不可卡死。
- 证据来源：仓库源码、README/计划文档、资产清单、Node 语法检查、Playwright 浏览器运行记录、Web Interface Guidelines。

5. 根目录 `AGENTS.md`：贡献者和后续智能代理的最小工作协议，指向上述文档。

## 审查模型

- 架构：C4 级别的容器/模块地图 + 状态机转移表。
- 功能：用户关键路径（开始 → 两条分支 → 小游戏 → 求婚 → 结尾）及异常路径（离线、缺资源、WebGL 不可用、触屏）。
- 质量：风险矩阵（影响 × 发生概率 × 可探测性）并映射到 P0/P1/P2。
- 界面：Vercel Web Interface Guidelines，重点关注无障碍、焦点、动画、触控、图片与性能。
- 工程：TDD 红—绿—重构循环，所有行为变更先写失败测试；每次发布执行离线 smoke test。

## 数据流与边界

```text
storyData(CONFIG)
       │
       ▼
Engine 状态机 ──► DOM 场景/对话/菜单/求婚层
       │
       ├────────► GameAudio（BGM + Web Audio SFX）
       ├────────► Minigame（Three.js/WebGL 当前实现）
       └────────► 资源路径（背景/立绘/照片/图标）
```

边界规则：故事脚本只描述意图；引擎负责状态与调度；子系统不得反向修改故事脚本；所有个人信息、路径和文案必须从 `CONFIG` 注入，禁止在渲染器中硬编码。

## 错误处理设计

- 启动阶段校验 `CONFIG`、脚本 label、资源路径和运行时依赖；失败时显示可读诊断，不允许静默黑屏。
- Three.js/WebGL 不可用时必须进入 2D 兼容小游戏或明确跳过路径，并继续求婚主线。
- BGM 缺失只降级为静音，但记录一次可见的诊断信息，不制造重复 404。
- 图片缺失显示占位图或跳过对应 slide；背景切换不得激活破图。

## 测试策略

- 单元测试：纯状态转移、脚本校验、资源清单校验、时间/物理计算。
- 浏览器 smoke：离线加载、两条分支、跳过小游戏、键盘选择、求婚接受、结尾重启。
- 可访问性检查：按钮名称、可见焦点、`aria-live` 对话、`prefers-reduced-motion`、触屏等价操作。
- 性能检查：首屏资源体积、WebGL/Canvas 帧率、纹理与粒子对象生命周期。

## 验收标准

1. 在无网络环境下从双击入口走到结尾，不出现未捕获异常。
2. 两条剧情分支均可完成，小游戏可玩、可跳过且不会阻塞主线。
3. 自定义姓名、日期、台词、照片和 BGM 只需修改 `storyData.js` 或资源目录。
4. 控制台不出现资源 404、未处理 Promise 拒绝或 `ReferenceError`。
5. 键盘、鼠标、触屏均有可发现、可操作且可见焦点的等价路径。
6. 每项修复都有先失败后通过的自动化测试或可复现 smoke 证据。
