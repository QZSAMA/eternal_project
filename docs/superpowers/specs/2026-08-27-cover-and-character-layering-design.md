# 开始封面与角色贴图防重设计

## 状态

- 设计日期：2026-08-27
- 视觉方向：用户已批准 C「游戏主视觉＋恋爱氛围」
- 实施约束：保留原生 HTML/CSS/JavaScript 与 1920×1080 固定舞台；所有行为修复遵循 TDD

## 目标

本次改动同时解决两个直接影响开场体验的问题：

1. 将当前纯渐变开始页替换为已确认的 C 方案，建立更清晰的游戏感、恋爱感与开始行动层级。
2. 修复角色在快速推进或跨剧情段落移动时出现的重复贴图、旧表情闪回问题。

成功标准是：开场封面与确认稿保持同一视觉语言；任意时刻同一角色最多出现在一个槽位；过期的延迟回调不能覆盖最新角色状态。

## 范围

### 包含

- 使用现有 `assets/images/photos/photo2.jpg` 作为开始封面主视觉，不新增来源不明的远程资源。
- 将开始页改为深夜蓝紫底、珊瑚橙主强调、冰青辅助强调的双人游戏视觉。
- 保留 `CONFIG.meta.title` 的动态标题能力，并在其上增加装饰性的 `OUR STORY` 主标题。
- 统一 `_show`、`_say` 和 `_hide` 的角色渲染与延迟切换取消逻辑。
- 增加单元测试、快速推进浏览器回归和 1920×1080 视觉检查。

### 不包含

- 不重绘全部背景、角色立绘或蒙太奇素材。
- 不调整故事台词、分支结构、小游戏玩法或求婚流程。
- 不引入前端框架、构建器或新的运行时依赖。
- 不在本轮更换已确认的 `photo2.jpg`；以后若生成新底图，只替换视觉资产，不改变页面结构。

## 视觉设计

### 构图

开始页继续占满 1920×1080 舞台。`photo2.jpg` 全屏铺底并轻微放大，人物位于中右区域；左侧使用深色渐变为标题、说明与按钮提供稳定对比度。最终页面只保留 C 方案，不保留终选样稿中的 A/B/C 切换器。

左侧内容自上而下为：

1. `CO-OP STORY MODE / ONLINE` 状态标识；
2. 两行高冲击力的 `OUR STORY` 装饰标题；
3. `SAVE SLOT 01` 与 `CONFIG.meta.title` 动态标题；
4. “两个人的主线任务，从这一刻继续”说明；
5. “开始双人旅程”主按钮。

右上角保留轻量的 `SYNC RATE 100% / PLAYER 1 + PLAYER 2` 装饰信息，强化双人游戏主题，但标记为装饰内容，避免辅助技术重复朗读。

### 配色与样式

- 夜空底色：`#080A18`
- 主强调色：`#FF684E`
- 辅助强调色：`#7EE6FF`
- 正文：`#FFFFFF` 与低透明度冷白
- 标题阴影：低透明度紫色偏移，不使用大面积霓虹光晕

背景覆盖径向暗角、左侧渐变和极淡扫描线；按钮采用轻量游戏 HUD 切角轮廓。图片右下角原始水印通过 `object-fit: cover`、放大裁切和底部暗角移出可视区，不进行破坏性图片编辑。

### 动效与降级

- 背景只做慢速、低幅度漂移；按钮与状态点使用克制的呼吸效果。
- `prefers-reduced-motion: reduce` 时关闭背景漂移、呼吸和过渡动画。
- 封面图片加载失败时，深夜蓝紫渐变仍必须覆盖整个舞台，标题和开始按钮保持可见可用。
- 键盘焦点沿用全局高对比焦点环；开始按钮继续使用原有点击和键盘激活语义。

## 角色贴图防重设计

### 已确认根因

1. `first_date` 将女主显示在 `center`，之后汇合到 `from_game_to_real` 又显示到 `right`。当前 `_show()` 只更新目标槽位，不清理其他槽位里的同一角色，因此女主会同时存在于两个位置。
2. `_show()` 和 `_say()` 的表情切换使用未受控的 200ms `setTimeout`。用户快速推进时，较早的回调可能在较新的指令之后执行，把旧图片重新写回槽位。
3. `_hide()` 没有取消槽位上尚未执行的角色切换，隐藏后的角色仍可能被旧回调重新显示。

### 角色槽位不变量

- 同一 `char` 在 `left`、`center`、`right` 中最多占用一个槽位。
- 一个槽位只能接受它最新一次渲染请求的结果。
- 被移动或隐藏的槽位不得被历史定时器重新激活。
- `dataset.char`、`dataset.expr`、图片 DOM 与 `is-show` 状态必须作为一个原子结果更新，不能各自滞后。

### 引擎内部边界

在 `Engine` 内集中增加三个小型职责，不引入新运行时模块：

1. **槽位失效**：为每个槽位保存待执行定时器和递增版本号。新请求先取消旧定时器并递增版本。
2. **唯一角色移动**：渲染角色前扫描三个槽位；目标槽位之外若存在相同角色，立即失效、清空角色元数据和可见状态。
3. **统一渲染入口**：`_show()` 与 `_say()` 都调用同一槽位渲染方法。延迟回调执行前校验版本号；只有当前版本可以写入图片和重新显示。

`_hide()` 同样调用槽位失效逻辑，并清空 `is-show`、`is-speaking`、`is-dim`、`dataset.char`、`dataset.expr` 与图片 DOM。这样隐藏动作不会留下可被复活的中间状态。

### 数据流

```text
show / say(expr) / hide
          │
          ▼
   失效槽位旧请求 ──────► clearTimeout + 版本递增
          │
          ├── show：清理其他槽位中的同一角色
          │
          ▼
   写入最新角色元数据
          │
          ├── 空槽位：下一动画帧显示
          └── 已显示槽位：淡出 200ms → 版本校验 → 换图并显示
```

## 文件改动边界

- `index.html`：调整开始页语义结构和文案；保持 `#startTitle`、`#startBtn` 等引擎依赖的 ID 不变。
- `css/style.css`：实现 C 方案视觉、响应式固定舞台样式和减少动画降级。
- `js/engine.js`：加入槽位失效、角色唯一性和统一渲染逻辑。
- `tests/engine-character-layer.test.js`：增加角色移动、竞态和隐藏回归测试。
- 浏览器测试只作为验证资产，不把一次性截图提交到仓库。

## TDD 与验证策略

### 失败测试先行

1. 女主从 `center` 移到 `right` 后，只有 `right` 的 `dataset.char` 为女主，`center` 不可见且无角色图片。
2. 同一槽位连续请求两个表情时，即使旧延迟回调被触发，最终图片和 `dataset.expr` 仍是第二个表情。
3. 角色在延迟换图期间被隐藏后，推进全部定时器也不会重新出现。

测试通过 Node 内置测试运行器、最小 DOM 假对象和可控假定时器执行，不增加测试依赖。

### 浏览器回归

- 从开始页进入游戏，分别走“游戏继续”和“第一次见面”两条分支。
- 在对话可推进阶段执行快速连续点击；每个采样点断言同一 `data-char` 的可见槽位数量不超过 1。
- 检查控制台无未捕获异常、图片 404 或过期回调导致的闪回。
- 在 1920×1080 与缩放后的 1280×720 视口检查封面人物裁切、标题可读性、按钮焦点和无横向溢出。
- 模拟 `prefers-reduced-motion: reduce`，确认封面仍完整且关键控件可操作。

## 验收标准

1. 开始页视觉与已批准的 C 样稿一致，且 `CONFIG.meta.title` 仍会显示。
2. 鼠标、键盘均可开始游戏；按钮具有清晰的 hover 与 focus-visible 状态。
3. 任何剧情路径、任何推进速度下，同一角色最多只有一个可见槽位。
4. 最新表情请求始终胜出；移动或隐藏后的角色不会被旧定时器重新显示。
5. `npm test` 与 `npm run check` 全部通过。
6. 两条剧情分支的快速点击浏览器回归通过，控制台没有新增错误。
