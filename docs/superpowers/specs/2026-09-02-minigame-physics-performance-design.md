# 小游戏物理与性能优化设计

- 日期：2026-09-02
- 状态：已批准实施

## 目标

在不改变“逆转的奶”胜负条件、数值配置和 Three.js/2D/skip 降级链路的前提下，让 3D 小游戏的移动、球体、敌人、粒子和拖尾按经过限制的 `dt` 更新，降低帧率变化造成的手感漂移和碰撞临时分配。

## 方案

`Minigame.loop()` 继续以毫秒 `dt` 驱动更新，并将单帧最大值限制为 50ms。3D 更新循环统一通过 `_dtSeconds(dt)` 和 `_frameScale(dt)` 换算时间：在 60 FPS 时保持现有每帧数值，在 30 FPS 或短暂卡顿时按真实经过时间推进。2D 路径已有秒级计算，继续复用同一 `dt` 输入，不复制规则。

碰撞检测改为直接比较 x/z 差值平方，避免每个球/敌人组合创建临时 Vector3。3D 更新每帧只读取一次 `performance.now()`；粒子和拖尾设置上限，达到上限时回收最旧对象，防止长时间运行造成 GPU/内存增长。所有资源回收仍集中在既有结束和移除路径。

## 不在本轮范围

- 不调整 `storyData.js` 中的速度、伤害、冷却、胜负条件。
- 不迁移 Three.js 到 ES Module；该项作为独立后续切片。
- 不引入运行时依赖、网络资源或遥测。

## 验收标准

1. 以相同总时长分别用 60 FPS、30 FPS 的 `dt` 步长积分，玩家/球体位移误差小于 `0.01` 个游戏单位。
2. `dt <= 0`、非数字和大于 50ms 的输入不会产生 NaN 或超速移动。
3. 3D、2D、skip 主线回调保持现有契约；触屏和键鼠输入不回归。
4. 碰撞更新不再调用 `Vector3.clone()` 创建比较向量；粒子/拖尾数量受上限保护。
5. `npm test`、`npm run check`、关系体验 smoke、触屏 smoke 全部通过。
