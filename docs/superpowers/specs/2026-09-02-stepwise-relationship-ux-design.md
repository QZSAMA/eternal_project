# 第一阶段关系体验优化设计

## 目标

在不改变离线架构和个人素材的前提下，先消除真实求婚现场最危险的交互问题：接受不能被误触，稍后回答必须是真实可用的路径，跳过小游戏后的叙事必须诚实，静音和照片回放必须可控。

## 范围

第一阶段包含四个相互独立、可单独验收的切片：

1. 求婚同意交互：取消自动聚焦“我愿意”；“让我想想…”保持原位并提供中性状态反馈；保留主线不离开。
2. 小游戏结果文案：`win`、`skipped`、`timeout` 结果由引擎记录；当前章节至少不再把跳过叙述成成功。
3. 封面静音：开始层提供静音切换，启动前即可选择；运行时 HUD 与封面按钮保持同一状态。
4. 蒙太奇控制：提供暂停/继续按钮和键盘等价操作；暂停时冻结当前照片、字幕和自动计时，并用可访问状态说明。

不在本阶段：角色/照片素材替换、去水印、女主剧情重写、小游戏触屏控制、帧率物理重构。这些需要授权素材或独立内容/输入设计。

## 交互设计

### 求婚

- 按钮出现后不主动聚焦任何按钮，避免键盘 Enter 意外接受。
- `我愿意` 继续进入既有结尾。
- `让我想想…` 不移动、不隐藏、不阻止聚焦；点击后显示一次轻量提示，例如“没关系，我们可以慢慢来”，并保持求婚层。
- Escape 可回到求婚等待状态，不触发接受；焦点样式保持可见。
- 不创建新的网络、存档或个人数据。

### 小游戏结果

- `Engine._call` 接收回调结果并写入 `Engine.lastMinigameResult`。
- 现有 `gaming` 文案改成对三种结果都成立的表达：成功时仍然温暖，跳过/超时时不声称玩家完成了操作。
- 结果字段只作为当前运行上下文，不持久化。

### 静音

- 开始层增加可见的静音按钮，使用同一 `GameAudio.setMuted` 状态。
- 两个按钮共享 `aria-label`、`aria-pressed` 和视觉状态；任何一个按钮切换都会同步另一个。
- 默认仍保持当前配置的静默 BGM 策略；静音只影响合成 SFX 和未来可选 BGM。

### 蒙太奇

- 蒙太奇层增加一个语义化按钮“暂停照片”/“继续照片”。
- 点击、Space、Enter 均可切换；暂停时取消/冻结当前 slide 的自动推进定时器，继续后从剩余时间继续。
- 显示 `aria-live="polite"` 状态，例如“照片已暂停，第 2 张”或“照片播放中”。
- 结束后清理按钮状态、定时器和焦点，不影响后续求婚流程。

## 架构与错误处理

- 保持 `Engine` 为剧情调度者；不把 DOM 选择器或按钮文案写进 `storyData.js`。
- 为求婚和蒙太奇新增的小状态均由 Engine 的生命周期清理，避免重复运行残留定时器/监听器。
- 缺少蒙太奇控制 DOM 时回退为现有自动播放，不阻断主线。
- 未知小游戏结果按 `skipped` 处理，并继续主线；不能因结果处理失败卡死。

## 验收标准

- 键盘焦点不会在求婚层自动落到接受按钮；Enter 不会在未明确聚焦接受时触发接受。
- 点击“让我想想…”后按钮位置不变，求婚层仍可见，提示可读。
- 跳过小游戏后的下一段对白不包含“已经奶到/成功”等不符合事实的断言。
- 开始前可切换静音，进入剧情后按钮状态一致。
- 蒙太奇可暂停、继续，暂停期间照片和字幕不推进；结束后仍进入 proposal。
- `npm test`、`npm run check`、两条 Playwright 主线 smoke 全部通过，无新增控制台错误或 4xx/5xx。
