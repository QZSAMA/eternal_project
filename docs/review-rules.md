# Eternal 可持续审查规则

## 1. 规则优先级

P0 是发布阻断项；P1 必须进入下一迭代；P2 可排入维护窗口。证据优先于计划文档，运行结果优先于“应该如此”的注释。

## 2. 架构规则

- 运行时不得依赖网络。第三方库必须 vendored、带完整性校验，并有不依赖它的降级路径。
- `storyData.js` 是内容和参数入口；姓名、日期、台词、媒体路径不得在引擎或小游戏中硬编码。
- 每个故事 label 必须可解析、可达或被显式标记为测试专用；未知指令和未知 label 必须报错并给出恢复动作。
- Engine 只负责调度；音频、小游戏、渲染和资源加载通过小接口交互，禁止共享隐式可变状态。
- 物理和计时使用 `dt`，不得把速度写成只在 60 FPS 正确的每帧常量。

## 3. 内容与资产规则

- README、实施计划、打包文件和源码的技术事实必须一致；每次架构变更同步更新。
- 角色立绘使用透明 PNG/WebP 或明确的抠图策略；交付前检查水印、版权、隐私和裁切。
- 资源清单必须可机器校验：路径存在、格式正确、尺寸符合用途、音频可解码。
- 真实姓名和照片属于个人敏感内容；仓库提交前确认授权，日志和截图不得泄露不必要信息。

## 4. UI/可访问性规则

- 使用语义化 `<button>`、`<main>`、标题层级和可读的按钮文本；图标按钮必须有 `aria-label`。
- 对话和异步状态使用 `aria-live="polite"` 或等价公告；Canvas 游戏提供文本说明和键盘替代。
- 所有交互控件有 `:focus-visible` 样式；不以 `outline: none` 或动画状态替代焦点反馈。
- 不使用 `user-scalable=no`；触屏操作提供点击/键盘等价路径并设置 `touch-action: manipulation`。
- 提供 `prefers-reduced-motion` 变体；长时间循环动画可暂停或关闭。
- CSS 禁止 `transition: all`；只列出实际过渡属性。图片声明尺寸，非首屏图片按需加载。

## 5. TDD 规则

任何行为变更必须按 Red → Green → Refactor：

1. 先写一个描述行为的失败测试并确认失败原因。
2. 写最小实现让测试通过。
3. 跑完整测试集，再重构并保持全绿。

仅文档、生成物和不改变行为的格式化可免于 TDD，但仍需运行语法/链接检查。

## 6. 发布门禁

每次发布至少执行：

```text
npm test
npm run check
无网络浏览器 smoke：开始页 → gaming 分支 → 跳过 → 求婚 → 接受 → 结尾
无网络浏览器 smoke：开始页 → first_date 分支 → 蒙太奇 → 求婚 → 接受 → 结尾
降级 smoke：强制无 WebGL → 2D 可进入；强制无 Canvas → skip 后返回主线
控制台：无 ReferenceError、未处理 Promise 拒绝、资源 404
```

## 7. 审查记录格式

每个问题必须包含：`[P0/P1/P2]`、文件与行号、可复现步骤、实际结果、影响、建议修复、验证方式。修复后保留原问题 ID 和回归测试链接。
